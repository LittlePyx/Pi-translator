# Pi Translator v0.9：扫描 PDF 渐进识别路线

## 当前阶段：受控的 Qwen OCR 临时文字层

Pi PDF 在检测到当前页面没有文字层时，显示一次短暂的“识别本页”入口。

- 点击只创建覆盖页面主体的可调整选框，不立即上传。
- 用户可以排除页眉、页脚、批注或大块空白，再明确确认。
- 官方 Qwen / 阿里云百炼配置确认后通过同一 Key 调用专用 `qwen3.5-ocr` 高精识别任务。
- 只接受原生 `ocr_result.words_info` 逐行文字与绝对坐标；通用视觉模型自行输出的 JSON 坐标不会进入文字层。
- 只处理当前页选定区域，不上传完整 PDF，也不在存储中保留截图。
- 入口只在扫描页提示中出现，不增加工具栏常驻按钮。
- 合格结果会生成当前标签页内的透明可选文字层；缩放时重建，换 PDF、刷新或关闭标签页后清除。

## 为什么只接入专用坐标 OCR

通用 OpenAI 兼容多模态接口通常可以返回识别文本，却不能稳定返回逐行坐标。直接把结果覆盖为页面文字层可能出现选区错位、双栏顺序错误或公式位置漂移。当前适配器因此仅接收官方 Qwen OCR 原生坐标字段，并继续保留严格校验和安全回退；其他接口只使用原有框选翻译。

## 后续阶段

1. 已建立严格的坐标 OCR 数据契约：要求归一化页坐标、唯一阅读顺序、置信度、块类型和受限文本长度全部有效；低置信度块与表格不会进入可选层。
2. 已接入 Qwen OCR `advanced_recognition` 适配器，并覆盖坐标解析、区域映射、缩放重建和换文档清理测试。
3. 下一阶段为双栏、公式、脚注和旋转页建立合成 PDF 回归样本；未通过的块继续回退到框选翻译。
4. 临时 OCR 结果保持只在当前页面会话中；在完成可靠文档身份、容量和用户控制设计前不提供持久保存。
