# Pi Translator v0.9：扫描 PDF 渐进识别路线

## 当前阶段：可调整的整页识别入口

Pi PDF 在检测到当前页面没有文字层时，显示一次短暂的“识别本页”入口。

- 点击只创建覆盖页面主体的可调整选框，不立即上传。
- 用户可以排除页眉、页脚、批注或大块空白，再明确确认。
- 确认后复用现有视觉模型、流式结果、LaTeX 校验、取消、队列和会话去重。
- 只处理当前页选定区域，不上传完整 PDF，也不在存储中保留截图。
- 入口只在扫描页提示中出现，不增加工具栏常驻按钮。

## 为什么暂不伪造 OCR 文字层

当前支持的通用 OpenAI 兼容多模态接口通常可以返回识别文本，却不能稳定返回逐字坐标。直接把结果覆盖为页面文字层可能出现选区错位、双栏顺序错误或公式位置漂移。Pi Translator 因此先提供可靠的整页识别与可调整确认，再逐步验证坐标型 OCR。

## 后续阶段

1. 已建立严格的坐标 OCR 数据契约：要求归一化页坐标、唯一阅读顺序、置信度、块类型和受限文本长度全部有效；低置信度块与表格不会进入可选层。
2. 对支持该契约的服务增加可选适配器，能力检测通过后才启用临时文字层。
3. OCR 结果默认只保留在当前页面会话；用户明确选择后才允许保存纯文本，不保存页面图像。
4. 双栏、公式、脚注、旋转页和跨页选择分别建立合成 PDF 回归测试后，才开放连续划句。
