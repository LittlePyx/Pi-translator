# PDF 表格与结论标题边界修复

## 复现与原因

使用用户本地 HATNet 论文第 8 页复现：`Table 3`、`Table 4` 和 `5. Conclusion` 合成一个表格对象。此问题发生在本地版面分析阶段，与翻译模型无关。

- 短标题的章节编号和标点被计入数字占比，`5. Conclusion` 被当作表格中的紧凑数值行。
- 段落构建未在新表注起点断开，`Table 4` 被拼入上一张表的 GPU memory / Inference time 末尾。
- 表格聚合没有把新的图表标题视为硬边界，包括已经完成聚合的相邻表格。
- 整表再次增加固定上下留白，覆盖了行级锚点原有的相邻内容保护，导致框选碰到上一张表的末行。

## 修改

- 判断章节标题时排除章节编号的数字证据；明确的结论、讨论等标题停止表格扩展，同时保留 `Method` 表头和真正的数值行。
- 新图表标题在段落构建时单独起块，后续换行表注仍可连续。
- 两张有独立表题的表格不再合并，重复运行聚合也不扩大范围。
- 整表截图留白受相邻内容边界约束，不侵入前一行、下一张表注或章节标题。

原论文第 8 页现在有三个独立表格（Table 2、3、4），结论标题和结论正文各自保留为普通文本块。截图和高亮使用同一源区域。
