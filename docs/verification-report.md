## 真实 Edge 扩展路径

- 使用解压后的 `.output/edge-mv3` 启动 Microsoft Edge，并以真实 Manifest V3
  service worker、content script、popup、options、Pi PDF 与 side panel 页面运行。
- 覆盖 Overleaf 和普通网页的划词按钮、右键触发、翻译卡片拖动、关闭、菜单收起、
  流式输出、翻译中固定侧栏、连续翻译与敏感字段跳过。
- 验证设置页能够从翻译卡片和快捷面板在新标签页打开；高级设置默认折叠，
  键盘导航与自定义视觉 API 自动绑定正常。
- 验证浅色和深色网页上的翻译界面会自动切换主题。
- 验证 Edge 原生 PDF 的 side panel 注册、标签页隔离、流式结果、重试状态和切换标签页清理。

浏览器原生右键菜单属于 Edge 浏览器外壳，Playwright 不能像网页元素一样直接操作。
验收通过真实扩展 service worker 触发同一 `contextMenus` 处理链，并检查最终 side panel
状态与界面，因此覆盖了右键命令后的产品逻辑。

1. 双栏可选择文本页；

## 升级、重启与数据安全

- 新增真实 Edge 重启测试：先写入旧版单接口配置和持久 Key，关闭 Edge 后使用相同浏览器资料目录重新启动。
- 旧版 `apiBaseUrl`、模型、语言、翻译风格、网页范围、白名单、侧栏宽度和 PDF 框选键均正确迁移到 v8 行为。
- 旧版单 Key 字段仍可读取，并会在下一次保存时迁移到默认 API 配置。
- 会话 Key 在模拟浏览器重启后清除；用户明确勾选本机持久保存的 Key 会保留。
- 配置导出不包含 API Key 或内部配置 ID；配置导入会清除 Key 并要求重新授权接口域名。
- 合成 PDF 区域截图不写入持久存储；会话缓存、历史和翻译检查点受数量与大小预算约束。
- 发布包密钥扫描未发现测试 Key、真实 API Key 或私钥模式。

## v0.8.1 工作区增量验收

本轮在 v0.8.0 候选包之后继续完成了文档级翻译记忆和保守型 PDF 选区吸附：

- “本文”抽屉只在固定侧栏中出现，可查看最近译句、采纳或忽略术语候选，并手动维护本文术语。
- 已确认的本文术语优先于全局术语表，并会注入同一文档的后续翻译请求；相关历史译句仅按当前选区匹配后限量注入。
- 文档身份使用匿名摘要；持久记录不保存网页 URL、PDF 文件名或截图。
- 本文记录限制为 40 个文档，每个文档最多 20 条最近译句、100 条确认术语和 20 条候选术语；快速连续写入使用严格递增时间戳，保证稳定淘汰最旧记录。
- PDF 智能吸附不再把视觉换行当成句末；尊重精确停在标点处的选区，并限制跨句、跨段和整页异常扩张。
- 框选公式数量与结构可信时，本地恢复识别原文中的 LaTeX，不再为细微格式漂移重复发送图片；确需校正时只进行一次限时请求，校正连接失败仍保留首次可用译文。
- 译文公式使用扩展本地打包的 KaTeX 输出 MathML；流式阶段保持源码稳定显示，完成后按设置渲染，且仅公式结果显示“源码/公式”微型切换。

## v0.8.2 重新提交增量（2026-08-04）

- 设置页的第三步改为“连接并自动配置”：读取当前 Key 可见模型后，优先保留可用的已有模型，否则从对话类模型中推荐文字模型。
- 自动配置会复用低消耗兼容性诊断，明确显示文字翻译、结构化/逐句能力和 PDF 图像能力，不要求普通用户理解兼容协议细节。
- 未手动绑定视觉配置时，扩展先测试所选文字模型，再测试最多三个名称上可能支持图片输入的候选模型；鉴权、余额或网络错误会立即停止，不会遍历或泄露 Key 到其他服务商。
- 服务商仍必须由用户选择；扩展不会仅凭 API Key 猜测或尝试多个 API 域名。自定义服务仍需用户明确填写 Base URL。
- Edge 审核测试说明已同步为新的自动配置步骤，并继续要求只在 Partner Center 中提供临时、低额度、可撤销的审核凭证。

## 已知非阻断项

- 构建器提示 Pi PDF 主 chunk 大于 500 kB；主要来源是 PDF.js。首次打开 Pi PDF 的资源均为扩展本地文件，因此当前不构成发布阻断。
- 浏览器原生菜单的像素级外观由 Edge 控制，无法由扩展或自动化测试定制。
