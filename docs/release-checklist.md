# Pi Translator 发布前验收清单

预计人工验收约 15 分钟。本文始终适用于 `package.json` 中准备发布的当前版本，不在文档中写死版本号。

## 0. 确认候选版本与工作区

```powershell
$releaseVersion = (Get-Content package.json | ConvertFrom-Json).version
$packagePath = ".output/tex-selection-translator-$releaseVersion-edge.zip"
$certificationNotesPath = "docs/edge-certification-notes-v$releaseVersion.txt"
git status --short --branch
```

- `package.json`、`package-lock.json`、扩展清单、`CHANGELOG.md` 标题和发布说明必须使用同一版本。
- `$certificationNotesPath` 必须存在；真实审核 API Key 只能粘贴到 Partner Center，不能保存进仓库。
- 广告源文件和导出图不是扩展发布提交的一部分，不得意外加入暂存区或 ZIP。
- 使用 Node.js 24；`.node-version` 是本地与 CI 的版本基准。

## 1. 自动化验证

```powershell
npm ci
npm run check:secrets
npm run typecheck
npm test
npm run test:e2e
npm run check:release
```

`check:release` 会重新生成 `$packagePath`，并核对源码版本、构建清单、Manifest V3、ZIP 路径、文件清单、内容及 SHA-256。任何一步失败都不能创建 tag 或上传商店。

- `build:edge` / `zip:edge` 生成 `build-info.json`，记录源码内容指纹、提交标识与构建时间；诊断报告必须能区分同版本号的不同产物。源码指纹不代表真实模型质量已验收。
- 默认 Edge 回归包含 `pdf-equation-numbering.spec.ts` 和 `pdf-product-workflow.spec.ts`。便携编号用例使用本地生成的测试 PDF，不能因缺少本机论文而跳过；HATNet 专项仍需显式配置 `PI_PDF_REGRESSION_SOURCE`。不要把可选跳过计为通过。
- 本轮开发验证不要覆盖原有同版本 ZIP。发布时先确定最终版本，再为最终精确包运行一致性与加载验收。

如果最终 Release 资产取自 GitHub Actions，应下载 artifact 内层的 `$packagePath`，单独记录其大小和 SHA-256，并对该精确 ZIP 重复结构检查与 Edge 加载烟测。不同 checkout 生成的静态 HTML 或 locale 文件可能只有换行格式差异；只有条目清单一致、可执行内容一致、静态文本归一化后内容一致且两侧门禁都通过时，才可采用 CI 产物。Release 上传时不得用本地重建包覆盖已经验收的 CI 文件。

## 2. 网页、Overleaf 与网页全文翻译

1. 在 Overleaf 选中一句英文，确认小型 Pi 按钮出现，取消选区后按钮消失。
2. 点击按钮，确认译文能够流式显示；翻译过程中固定到侧栏，流式输出应继续。
3. 在普通网页选中文字，通过右键菜单和快捷键各翻译一次。
4. 打开浏览器侧栏，连续翻译两个选区，确认最近译文导航不会重复调用 API。
5. 在一篇不足 100 段的外文文章中启动“翻译网页正文”，确认直接开始翻译，不出现长文确认步骤。
6. 在一篇超过 100 段的外文长文中启动全文翻译，确认先显示识别段数和预计批量请求次数；确认前不应出现译文或接口请求。
7. 打开“调整范围”，依次测试“全部正文 / 当前章节 / 从当前位置”。章节必须停在下一个同级或更高层标题之前；当前位置以上内容应被排除。每次切换都实时更新段数与请求估算，仍不调用接口，并允许继续逐段微调。
8. 确认长网页后等待全文完成；悬停译文时只能在左侧细线外显示紧凑的本段操作入口，不得遮挡文字、预留右侧空白或改变页面高度，点击后操作栏应在译文下方展开；再切换“双语 / 译文 / 原文”，检查公式、代码块、表单和未译失败段没有消失。刷新同一页并重新打开 Pi，确认匹配译文恢复且未变化段落不重复请求。

通过标准：没有重复按钮；关闭卡片或点击页面空白处后菜单正确收起；浮层与浏览器侧栏不会同时遗留冲突状态。

## 3. 网页区域框选

1. 分别打开网页内固定翻译侧栏和 Edge 浏览器侧栏，确认空状态、翻译中和已有译文状态的顶部都显示“框选网页”；点击后在普通文章文字上拖出选框并调整位置与四角尺寸。按 `Escape` 取消时网页内侧栏应恢复且不产生请求；工具栏快捷面板的“框选网页区域”仍应可用。
2. 确认界面应明确说明网页框选将使用多模态模型；在再次点击发送前不得截图或调用接口。
3. 分别在网页文字、渲染公式、图像或 Canvas 上框选，确认都只在再次点击发送后提交局部截图，不会改走文字接口。
4. 在包含密码、验证码或支付字段的区域框选，确认发送被阻止。
5. 从成功结果和失败提示分别进入“调整区域”，确认恢复原矩形；进入“重新框选”时应从空白开始。两种入口在再次确认前都不得请求 API。
6. 从空白框选界面按 `Enter` 建框，以方向键移动、`Shift + 方向键` 缩放、`Ctrl + 方向键` 细调；按 `Escape` 取消并确认不产生翻译请求。
7. 确认不存在整页、自动滚动或连续截图入口。

通过标准：发送内容与确认界面一致，截图只覆盖当前可见页中的选框范围。

## 4. Pi PDF 文字、框选、全文翻译与导航

1. 打开一份含文字层的论文，划选跨行句子并翻译。
2. 打开右侧翻译栏，确认 PDF 在剩余区域居中；关闭侧栏后恢复全宽居中。
3. 点“框选翻译”，在含文字层区域框选一次，应优先提取文字；在扫描页框选时才调用视觉 API。
4. 缩放一次，确认当前页和大致阅读位置保持不变。
5. 翻译一句后添加轻标记，打开“查看本文标记”，测试定位、复制、删除和重新打开后的恢复。
6. 在一份普通文字 PDF 中点击“译全文”，确认第一次只在本地预览段数；分别测试整篇、当前页和自定义页码，确认范围错误不会产生请求。
7. 使用一份双栏论文开始全文翻译，检查译文按页和阅读顺序排列；点击完成译文应返回对应原文。重点检查以 “Figure 2 clearly illustrates…” 一类图号引用开头的正文：首行和后续换行必须形成同一段、点击后全部行落在同一个准确高亮区域，且不能把后续行并入前一个公式段；真正带 `Figure 2.` / `Figure 2:` 标题分隔符的图注仍可作为版面中断。再检查一张含坐标轴、刻度和图例的矢量图，以及一张多行多列表格：预览中应各自只形成一个图表/表格对象，不得把刻度、数据点、图例或单元格铺成零散段落；智能多模态开启时，每个对象只产生一次视觉请求，普通正文仍使用文字接口，表格译文应保持行列并可横向滚动；点击结果应高亮整张图/表。关闭智能多模态时不得发送对象图像。请求进行中切换到其他标签页或窗口并停留至多个混合文字/视觉批次完成，确认任务继续发送且未变成暂停；切回 PDF 后应自动同步完整进度，不需要点击“继续”。文字模式、混合智能模式和含公式的统一多模态模式各验证一次。暂停、继续、停止、单段重试和重新翻译均只影响当前范围。
   特别检查双栏正文上方或中间的通栏 Figure 图注：图注多行必须合为一个全宽对象；栏内 `x(0) in Figure 2. Instead...` 一类正文引用仍属于正文。图注含公式但视觉模型未另列 `formulaLatex` 时，只要对象译文非空仍应显示译文，不得回退为“已保留原图”；独立公式段缺少可靠公式元数据时仍应保留原式。
8. 使用一份含扫描页和公式的 PDF，确认全文预览只在本地报告正文、含公式段落和无文字层页数；“公式文档统一多模态（推荐）”默认开启，但点击“开始”前不得截图或请求。点击“开始”即确认当前范围的本次任务：只要文档检测到公式，当前范围内全部段落都必须使用同一个视觉模型，不得混入文字接口；每段仍按原文位置返回，扫描 OCR 可中途停止。关闭统一多模态后，扫描页不得发送，独立公式块必须原样保留，其他正文才可使用文字接口。
9. 完成部分或全部全文翻译后，测试纯译文、图文双语 Markdown、带原页图的可打印 HTML 和“原页对照 PDF”。图文双语 Markdown 应在对应段落前内嵌已检测图表和表格的本地截图，不能把截图混入纯译文或复制结果；对照打印页应按原始尺寸完整保留每张原页，不得用译文覆盖原文、公式、图片、图表或表格；每张原页后应紧跟按阅读顺序排版的同尺寸译文页，公式必须渲染，放不下的内容必须自动增加对应译文续页，不得裁切或缩成难以阅读的小字。所有截图与页图都应在本地生成，全程不得产生翻译、OCR 或视觉接口请求。刷新同一 PDF 后确认会话恢复。可选开启“关闭后保留译文”，并检查本机文档库、容量与备份；显式保存的标题、网址、文件名及出处不是匿名统计。

通过标准：文字清晰、选区可调整、工具栏没有重复入口或遮挡；无法定位的旧标记明确显示“原文位置已变化”。

### 含公式段落的降级验收

- 对于连续排列的 Table 2 / Table 3 / Table 4，每张带独立表题的表格应分别成块。随后 `5. Conclusion` 等短章节标题及正文不得进入表格；点击高亮和导出截图不得因留白碰到上一张表的末行。跨行表注仍须完整，表内 `Method` 等表头和数值行不得散落出来。

- 含公式段落请求使用单份公式登记（`refs-v1`）：每个公式只生成一次 LaTeX，原文和译文引用同一编号。模拟编号缺失、重复、未知编号、顺序调整、单个公式结构损坏及模型标记不确定；仅问题项显示短编号核对入口，其余公式及正文应正常保留，不得整段变成“公式见原文”。流式生成时不得露出内部编号模板。
- 旧格式结果仅保留逐项确切对应的公式；禁止因数量相同便按位置覆盖符号、字体、上下标或顺序。原文 `a+b` 与译文 `a-b` 不得自动修成成功结果。公式登记完整但未翻译正文时，也不得标为翻译成功。
- 中文与公式无法可靠分离时，应原样保留为“待核对译文”，不得因一个未标记的 `∈`、希腊字母或破损 LaTeX 丢弃整段中文；阅读器及 HTML/PDF 导出不渲染这类草稿中的数学内容，待核对状态需保存并可恢复。模型仍返回原文、没有目标语言正文或仅有公式时，应保留原文并显示具体原因，不再用“已保留原式”暗示正文翻译成功。
- 有待核对公式时默认展开完整段落的本地原文截图；点击问题项短编号应展开同一截图，不猜测单个公式的位置。切换阅读/对照、下载 Markdown/HTML/PDF、重新打开同一文件均不得发起额外模型请求。图文双语 Markdown 应包含待核对段落的本地原文截图；所有导出应保留待核对提示。核对行内公式不被强制独立成行、编号不重复、长公式可滚动，且 HTML/PDF 只渲染通过局部校验的公式。
- 保存会话与显式本地保留时，公式只保存一份登记内容，原文模板只留引用顺序，不附加保存源正文、截图或文件地址；恢复后重新检查引用关系。
- 同一数学表达式重复出现时允许复用内容编号，但原文与译文出现次数必须相同，每个位置有独立标识；不能将两处正常的 `N` 都替换成待核对编号。裸露但完整的 LaTeX 只有与识别原文确切对应时才能补登记，无法对应或破损时仍提示核对。
- 用本地 HATNet 第 4—5 页检查跨页 `F ∈` 与下一页维度表达式一起处理；单选其中一页时提示范围截断并禁止启动，不得自动扩大范围。密集段只在不切断字形／公式组的边界划分图像，请求数须计入预览，但阅读视图仍是一段。点击应高亮两页各自原文；暂停后继续不重发已完成子区域。
- 源区域内有 (12)、(13)、(14)、(15) 时逐个核对返回编号。缺号、重复编号或带入相邻区域编号都应给出局部警告，保留其他译文与公式。注意编号齐全只能证明覆盖，不能证明符号语义正确；最终仍须在用户明确启动后，用真实模型核对原文。
- 有可靠本地公式行时，以 `sourceEquationId` 绑定原文编号；模拟全部漏掉 `tag`、登记数组反序、行标识未知／重复／冲突，确认 (1)–(4)、(16) 不依赖模型生成编号或数组顺序。行号与公式主体独立显示，组公式逐行编号。数学主体待核对但行号已绑定时不能误报缺号；不能仅因补号清除数学不确定。预览、HTML、Markdown、实际打印 PDF 与会话恢复应一致。阅读视图切回原文并触发适宽重绘时，高亮仍需覆盖原区域。
- 点击“重试本段”才发起该段的新请求，不得顺带继续其他暂停段落。重试失败保留先前结果；重试成功移除该段待核对提示。恢复已保存进度后仍要保留待核对状态。

### 核对清单、试译与请求上限

- 核对清单按尚未翻译、失败、公式待核对及保留原文筛选；排除范围外段落及有意保留的参考文献。点击条目回到原文。标记“已人工核对”只记录本次结果的人工状态，不删除警告、不证明公式内容正确、不发起 API 请求；刷新可恢复。公式内容或译文变化后原确认失效。
- “试译本段”只发送用户选择的一个段落或该段视觉子区域，不启动全文队列；完成后可继续全文并复用该结果。试译前选择段落及改变范围不发请求。公式文档需明确提示视觉发送范围与预计子区域数；试译不扩大整篇视觉授权。
- 任务请求上限按文字批次、视觉区域与 OCR 页累计，0 为不限。达到上限时暂停，不丢弃已完成结果，提高上限后可继续。这个次数不等于账单中的实际 HTTP 调用数，接口内部自动重试可能额外计费。
- 只统计接口实际返回的有效 token 数；未返回用量时显示未知，不当作 0。缓存结果不重复累计 token。金额按用户填写的单价估算，未实现按金额自动停止的预算。

### 费用估算、文档库与带出处摘录

- 设置中可添加 / 更新 / 删除模型单价，空值不等于免费，明确填写 0 才是零单价。模型 ID 与 API Base URL 一起匹配；更换模型或接口后不得复用旧单价。配置导出 / 导入保留单价，不包含 API Key。
- PDF 全文面板的“费用”按需展开；单段试译、继续到后台完成后累计已报告用量。展开内容不能遮挡设置或任务操作。文字与视觉接口分别匹配模型，人民币 / 美元分别计价，不隐式换汇。剩余文字粗估不包含视觉块、纯公式、代码、提示词、图片、OCR 和自动重试；未报告或失败请求的费用仍未知。用量只属于本次任务，不作为跨会话账单。
- 本机文档库逐篇显示已保存译文，支持名称 / 类型 / 语言搜索、手动命名、预览、Markdown 导出与两次点击删除。命名不自动读取网页标题或文件名；译文继续保存时名称保持。删除一篇不得影响另一种类或其他文档。清除后检查关联名称也被移除。仍在翻译并开启保留时，后续结果可能再次保存，界面需说明。
- 固定网页 / PDF 记录不随最近记录淘汰；达到 6 份或 100 万字符时不得静默移除固定记录。修改固定记录应同步独立副本，取消固定回到最近记录规则。备份往返保留名称、固定状态、公式登记、核对提示与 PDF 标记；不导出 API 配置或 Key，标记中的原文、出处和笔记需在说明中明示。格式错误或导入后超过容量时不写入现有记录，同身份记录保留较新的版本。
- 从文档库选择原 PDF，核验 SHA-256 与段落签名后恢复阅读；改名后的同一文件可恢复，错误文件不套用译文，不发送请求。旧记录无 SHA-256 时核验原文件身份，不宣称任意改名恢复。缩放重建页面不得清空文件指纹、文档恢复身份或修正撤销状态。
- Ctrl+F 的默认范围随阅读视图变化，原文 / 译文 / 同时搜索可切换，译文命中滚到对应段落，原文命中显示对照并标出原页位置。清除 / 关闭搜索去除高亮，搜索不产生接口调用，300px 宽下控件不得截断。
- PDF 完成或暂停后可逐段修正文字；翻译中禁用修正。公式引用、编号与命令保持只读，禁止注入新公式；取消、保存、撤销、恢复和导出均验证。既有回退与核对提示继续显示，改动后原人工确认需失效。300×420 深色修正框的正文独立滚动，页脚不得覆盖输入内容。
- 导出库内译文按 `documentSignatures` 原始顺序排列，公式引用展开为 LaTeX，保留核对提示；不补造原文、页码或来源。360px 设置页不得横向溢出，操作按钮可以换行，正文保持可读。
- “本文标记”可编辑标题 / HTTP(S) 链接 / DOI / 个人笔记。单条复制与复制全部都包含出处和实际 PDF 页码，公式内容不改写，链接括号正确编码。无 DOI 时不生成 DOI；危险协议或无效 DOI 阻止保存。编辑 / 导出不发翻译请求。
- 重新打开同一 PDF，已保存标记的出处仍可编辑并复制；普通网页未保存标记只保留当前页面；显式保存的摘录单独存储，刷新可恢复，不写入 PDF 标记存储。检查本文标记、库内搜索、笔记编辑、v3 备份、旧版导入及重复原句无法唯一定位；达到 30 页 / 每页 100 条 / 4 MB 不自动淘汰已有记录。测试中的 token、译文与 DOI 可用演示数据，必须与真实模型和真实论文验收分开记录。

## 5. Edge 原生 PDF

1. 用 Edge 原生阅读器打开 PDF，选中文字后右键“使用 Pi Translator 翻译选中文本”。
2. 确认译文在 Edge 原生侧边栏流式显示。
3. 切到其他标签页后侧边栏不跟随；切回原 PDF 时会话仍属于原文档。

## 6. 设置、安全与发布文件

### 界面与阅读布局

- 浅色 / 深色下核对设置、快捷面板、PDF、翻译卡片、Edge 侧栏和网页双语控制条：普通文字用中性色，主要操作与次要操作有明确层次，错误和核对信息仍可见。按钮键盘聚焦后保持角色和清晰焦点环。
- 顶部“保存更改”通过 `form="settings-form"` 提交原设置表单，仅在有改动时显示；已保存状态不常驻占位，错误反馈仍显示。仅改价格、翻译偏好、修改 API 后保存，以及文字 / 视觉配置切换均需验证。高级配置默认折叠，深链接仍可展开并聚焦正确字段。
- 快捷面板默认只显示语言与翻译操作；接口、网站暂停、使用方法和低频入口在“更多”中，完整设置从右上角齿轮打开。缺 Key、模型或授权时，“接口与快捷键”自动展开并移到操作前；仅缺快捷键时不打断默认操作。
- 文档库默认显示列表而非编辑表单；名称可展开预览，更多菜单支持键盘打开 / Escape 收起，重命名可保存或取消。预览只显示译文和原有核对提示，不把导出的说明头当正文。搜索、导出、逐篇删除、批量清理和窄屏布局均需验证。
- 文档库顶部不常驻显示版本、API 状态或隐私横幅；空间统计和批量清理从右上角管理菜单展开。版本与数据说明仍可在支持页找到。PDF 的试译和请求上限默认折叠；切入阅读模式收起设置与试译，费用也按需展开。
- 费用页将接口 / 模型与币种 / 输入 / 输出单价分组；结果设置按历史与侧栏、翻译过程、PDF 框选分组。PDF 已完成阅读不再显示满进度条，零核对项时不占阅读区；有回退、警告或人工核对记录时仍显示清单。
- 360px 宽窗口不横向溢出；360×420 矮侧栏展开长原文时，原文可单独滚动，译文开头保持在底部操作栏上方，正文不缩小。复制反馈不改变操作栏高度。数学表达式可横向滚动，编号仍跟随原行。
- 新版 Pi 标识在界面中使用灰度呈现，原 PNG 不改写。源字段与标题定位器随新文案更新；测量尺寸考虑 Windows 的亚像素舍入。静止 / 悬停 / 键盘聚焦分别建立测试状态，不用残留鼠标位置推断视觉状态。
- `npm run test:design` 生成实际扩展界面截图；文档与模型返回为演示数据。截图不是设计稿或真实模型质量验收。参考官方 [OpenAI](https://openai.com/brand/)、[Apple HIG](https://developer.apple.com/design/human-interface-guidelines/layout)、[Fluent](https://fluent2.microsoft.design/color) 与 [Material](https://m3.material.io/styles/typography/applying-type)。
- CI 在生产构建和功能回归后运行 `npm run test:layout:built`，检查不同状态、浅深色与窄窗口布局，失败则阻止打包并上传诊断。`pdf-reading-workflow.spec.ts` 同时纳入功能回归，覆盖译文搜索、修正、固定、备份与原文件核验。CI 配置通过本地同命令验证，远程运行结果单独记录。

1. 从结果菜单打开完整设置，确认新标签页正常出现。
2. 测试当前 API 连接和模型读取；视觉模型可用时确认自动绑定。
3. 导出配置，确认文件不包含 API Key。
4. 核对 `$packagePath`、`$certificationNotesPath` 和 `docs/edge-store-submission.md`。
5. 用 `git diff --cached --name-only` 再次确认提交中没有广告素材、密钥、`.env`、测试报告或构建目录。

### 本轮术语与材料补充

- 已确认的本文术语可在 PDF 全文更多菜单检查：候选带上下文，预览后仅改本段文字，公式登记 / 字体 / 编号不变；人工校订段只读，保存后可在校订历史恢复。不因词条未出现就断言模型译错。
- 密集表格须同时有完整识别表与译文表，行列对应、有序数值一致；表题有译文但表格主体缺失仍是待核对，不能当作成功。保留原图、原始响应和具体原因，不移除校验或反复请求。数学字体与无文字层样本需单独验收；样本区域通过不代替整篇保证。

### 精确 ZIP 安装与跨版本升级

`tests/e2e/release-upgrade.spec.ts` 是旧设置迁移与重启检查，不能替代跨版本验收。另以 `release-package-acceptance.spec.ts` 在独立临时 Edge 档案运行精确 ZIP：

```powershell
$env:PI_RELEASE_PACKAGE_ZIP = '最终 0.16.0 ZIP 的绝对路径'
$env:PI_RELEASE_PUBLISHED_BASELINE_ZIP = '正式发布 0.15.0 ZIP 的绝对路径'
$env:PI_RELEASE_DEVELOPMENT_BASELINE_ZIP = '最近开发 0.15.0 ZIP 的绝对路径'
$env:PI_RELEASE_STORAGE_FIXTURE = '脱敏本机保护样本 JSON 的绝对路径'
npx playwright test tests/e2e/release-package-acceptance.spec.ts --output='新的验收目录'
```

记录三个 ZIP 的 SHA-256 和来源。保护样本只含白名单旧译文 / 公式 / 人工修正 / 历史、固定记录、术语出处、摘录笔记与假凭据；不读取日常 Edge 档案或真实 Key。在同一临时安装路径解包新版本，并调用扩展 Reload，等新后台运行 0.16.0 后再完全退出 / 重启 Edge；仅替换文件后重启可能仍执行旧后台缓存。必须确认扩展 ID 不变、0.15.0 → 0.16.0、整份受保护本机值相等、可续读与备份、再次重启仍相等。历史收藏键也须保留，但不包含在当前文档库备份中。仅会话数据应先由用户显式保留，不能把 Edge 会话生命周期误判为升级删除。

最终 ZIP 可解压后通过 `PI_E2E_EXTENSION_PATH` 指向现有模拟提供方功能夹具，避免复验时重新编译取代已核验的 ZIP；测试结果应明确标识模拟请求与实际旧结果离线回放，不据此增加模型语义质量结论。未设置路径的精确包用例会跳过，跳过不等于验收通过。
