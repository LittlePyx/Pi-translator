# Pi Translator 前端设计原则

这份记录根据用户在网页翻译、工具栏、侧栏、设置、PDF 阅读和人工修正界面上的反馈整理；它是后续设计的工作依据，不是不可更改的规则。

用户提到的 OpenAI、Apple 和 Google 是可参考的设计方向。借鉴其公开设计指导中的简洁、清晰层级、响应式布局和可读性，不复制品牌标识，也不为了追求某种风格牺牲 Pi 的阅读工作流。参考：[OpenAI 界面指导](https://developers.openai.com/plugins/concepts/ui-guidelines)、[Apple 设计原则](https://developer.apple.com/design/human-interface-guidelines/design-principles/)、[Google 内容布局](https://developer.android.com/design/ui/mobile/guides/layout-and-content/content-structure)。

## 内容优先

- 一眼看到当前任务和主要结果。阅读和翻译界面优先呈现译文、原文及必要的上下文；来源、状态、帮助与辅助操作退居其次。
- 少用分割线、重背景、大阴影和重复卡片。原文要清楚可读，但视觉重量低于译文；操作区自然接在内容之后，避免生硬切断。
- 一屏先呈现当下需要的信息。高级配置、低频操作和解释按需展开，但常用操作不能藏得难找。

## 克制而统一

- 延续现有黑白灰中性色、留白、细边框和轻阴影；强调色主要用于焦点、状态和必要提示，避免多个视觉中心。
- 页面、子页面、侧栏、弹窗和工具栏共享字体、间距、圆角、按钮及反馈风格。狭窄区域优先保证内容、标签与控件完整，不让文字被挤压或竖排。
- 主要动作清楚突出，次要动作轻量；文字与图标保持明确含义。选择、悬停、焦点、禁用与深色模式需要同样可辨。

## 自然的操作流程

- 用用户的任务组织入口，明确下一步和当前状态；不堆叠术语、过程说明或过多同时可见的选项。
- 自动辅助应安静、可理解、可忽略；权限、费用、外发内容和实际状态在需要决策时清楚说明，不把未验证的配置说成成功。
- 操作可返回、可取消；切换视图、打开设置或提示时保留原资料、人工修改、阅读位置和未保存草稿。

## 验收

修改后按实际入口检查桌面和窄屏、浅色和深色、正常与错误状态，关注文字裁切、按钮遮挡、滚动和键盘操作。截图与离线模拟只能证明被覆盖的场景；未经验证的真实服务和用户环境不应声称通过。
